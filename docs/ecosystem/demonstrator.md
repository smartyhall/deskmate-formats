# The idealized DeskMate enthusiast system

An operator-directed, living historical demonstration of a richly
equipped DeskMate user's computer, as if a dedicated customer had
ordered the full complement of DeskMate releases and companions from
Radio Shack over the platform's commercial lifetime.

This is an **idealized retrospective**, not a recovered original
household system or a claim that every program was sold simultaneously.
The primary exhibit should use a plausible late DeskMate 3.x machine;
earlier and incompatible releases may require separate profiles.
Distinguish period-correct hardware and original software from modern
reconstruction conveniences and experimental font conversions.

## Separate exhibit and research machines

Use the already verified 86Box Tandy 1000 RSX / 25 MHz 386SX / VGA /
enhanced audio / DOS 5.0 profile as the initial candidate. The 1993
Radio Shack catalog identifies the RSX as a 25 MHz 386SX system, with
1 MB standard RAM, 9 MB maximum and a 52 MB hard-drive option; the
current research profile has 4 MB RAM. Select a practical historically
plausible memory/drive configuration after hardware and DOS limits are
verified, retaining a documented minimal official configuration and
an expanded enthusiast profile. Do not imply that every choice was a
standard factory offering. Preserve the verified experimental baseline
unmodified. Maintain per-release isolated installation snapshots and
a separate integration/exhibit clone. Retain earlier Tandy graphics
and audio profiles where a program behaves differently.

Install in stages. Inventory filesystem and configuration changes,
record actual runtime and resource versions, test standalone and desktop
launch, document conflicts, and preserve coexistence without blindly
overwriting shared modules. Native runtime wrappers may be required.
Use period-appropriate DOS configuration and original drivers where
available. Confirm menu capacity, paths, conventional memory, clipboard,
printing, fonts, audio, and file associations.

## A coherent fictional user's computer

Rather than an empty collection of program icons, populate the software
with an original, internally consistent fictional household and small
business (no real personal records). Example demonstration projects:

| Workspace | Native projects |
| --- | --- |
| Home office | Correspondence, household budget, address book, appointments, invoices, inventory, expenses |
| Business | Customer records, mail merge, sales forecasts, charts, labels, monthly reports |
| Publishing | Newsletter, letterhead, advertising flyer, plan, typography specimen and clip art |
| Household | Recipes, menu planning, shopping, household inventory, family timetable |
| Music and graphics | Original three-voice music, sampled instrument, sound effect, drawings |
| Education and hobbies | Study and writing projects, available educational applications, game saves if appropriate |
| Communications | Local or simulated historical sessions only; no real financial data or legacy network/account access |

Demonstrate real cross-application interactions: data-to-graph-to-report,
address book/database-to-mail merge, Draw-to-Text/Filer/publishing,
graphic/text clipboard transfers, save/reopen and print. Use original
software first; label independently generated modern import files
and any new fonts as later extensions. Retain original eligible
native-written synthetic files with hashes, exact version, user actions
and expected results. Reuse them in the portable preservation tests.

Produce a historical-style product inventory, annotated desktop layout,
operator walkthrough, setup recipe, exact per-app compatibility matrix,
and offline demonstration script, with missing titles represented
honestly. The installation image and original commercial materials
stay private; the published reconstruction recipe references authorized
user-supplied media and independently authored configuration and examples.

## Definition of done (incremental)

For each new title: acquire and verify media, install privately, launch
from its intended environment, create at least one original document
where applicable, save/reopen, capture the result, catalogue file
identities, and update the recovery workbench's identification/extraction
plan. A title that lacks media or cannot coexist remains a documented
gap, not a counterfeit substitute. Private snapshots permit comparison
of software releases and cross-application system resources.

This is a long-term secondary project. It must not monopolize the next
Draw/font campaign. Build it incrementally as adjacent format research
and acquisitions become useful.
