# DeskMate ecosystem catalog and recovery roadmap

This is the secondary research track authorized by the operator on
2026-11-19. The long-term objective is recovery and interoperability for
files actually left on a DeskMate system, not only those created by the
bundled applications. The core formats and current Draw/font research
remain the immediate priorities.

[Machine-readable catalog](catalog.json) records 42 products and toolkits.
The [TVDog reference library](tvdog-reference.md) links recovered media and
documents to exact source identities, a release coverage matrix and
research leads. A catalog listing, a downloadable archive, an acquired
disk, a verified installation and a decoded native format are distinct
facts.

The recovered 1988 Express Order Software Buyer's Guide identifies eleven
additional products. The catalog records the interface as advertised where
the guide displays the DeskMate logo, with exact runtime and native file
support still open. The accompanying purchase evidence links named products
to exact guide pages. [Period purchase evidence](demonstrator-purchase-facts.md)

## Scope and evidence

Separate dedicated DeskMate applications, applications with a bundled
DeskMate runtime, Tandy/partner companion modules, freeware/shareware,
development utilities, services, and ordinary DOS programs launched from
the desktop. Do not infer that a product uses DeskMate merely because it
was advertised by Radio Shack or supports Tandy hardware. Identify
platform and DeskMate generation; maintain other TRS-80 and Windows
products as separate branches. Preserve exact edition suffixes, publisher,
release dates, international variants, Radio Shack catalog numbers and
source citations. Record missing information as null. Do not collapse
different releases with incompatible formats.

For every product, progress independently through:
1. Historical identification and source verification (prefer box/manual,
   catalog, contemporary review or actual program).
2. Private media acquisition and hash inventory, including original
   disk labels, image format, lineage, acquisition source and rights.
3. Disposable installation and repeatable launch, with runtime and
   resource dependency inventory, platform/profile, install choices
   and observed collisions.
4. Native file inventory: extension, magic/structure, role (document,
   settings, resource, cache, executable), native writer and shared API.
5. Controlled original examples: empty/minimal, feature variants, edits,
   save/reopen, exact provenance, malformed probes where useful.
6. Independent identification, extraction, rendering and, when qualified,
   writing; document coverage and limitations.
7. Recovery integration and cross-application tests.

A release should eventually have a stable catalog identity plus its
own versioned record for media hashes, program/module fingerprints,
file signatures, sample provenance, supported versions, native workflow,
portable tests and preservation output. When extensions collide (e.g.
DOC or FNT), identify by structural evidence instead of extension alone.
Use unknown/ambiguous classifications rather than forcing a parser.
Never mutate a recovered original. Preserve opaque files and manifest
their status in the recovery workbench even before decoding is possible.

## Initial sources and priorities

The 1990 and 1992 Radio Shack catalogs (printed pp. 180 and 188/190)
and contemporary November 1989 review supply initial product evidence.
The 1993 catalog provides later continuity and machine context.
Catalog PDF text was accessible but page-image requests failed; confirm
original scans and exact editions during the expanded inventory.
Archive indexes are acquisition leads, not proof of intact disks.

The first acquisition priorities are Express Publisher, Q&A Write and
its DMQNAFNT.TXT font-import note, and First Publisher (operator
archive already supplied). Also investigate Lotus Spreadsheet, FilePro,
Home Organizer, Business Graphs, Macros, HomeWord II and Quicken.
Locate the original DM_PROGS.TXT list by Kenneth Udut, DESKMOR.TXT
developer announcement and other original catalog/listing documents.
Search beyond Radio Shack: original publishers, trade publications,
shareware archives, user groups and preservation collections. Track
negative findings and missing media, without inventing download links
or discarding leads.

The [acquisition handoff](acquisitions.md) records acquired archives
and prioritized leads. The [TVDog archive mirror protocol](archive-mirror.md)
sets out the operator-approved complete private mirror and derived public
reference index. See the [demonstrator plan](demonstrator.md)
for the companion living-system project.

## Publication

The project publishes independently authored specifications, tools,
derived facts, source links and eligible synthetic native documents
under existing licensing and repository audit rules. Commercial
executables, original disks, proprietary resources, user records,
passwords, licenses/serials and unapproved screenshots remain private.
Do not create a publicly distributed preinstalled commercial software
image. Publish only independently authored reconstruction recipes,
configuration, provenance, eligible synthetic documents and test
results. An operator's possession of an archive is not proof of
redistribution rights. Preserve original notices and rights information.
