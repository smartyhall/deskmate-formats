## FF1 outlines

The inner directory locates a separate record for each character code. Each
record starts with a 14-byte little-endian header.

| Byte | Field |
| ---: | --- |
| 0 | Profile word 1 in every sampled record |
| 2, 4, 6, 8 | Signed minimum X, minimum Y, maximum X, maximum Y |
| 10 | Contour command bytes |
| 12 | Auxiliary section bytes, including its own header |

The bounds match the minima and maxima of the **stored control points**
for all nonempty streams. Actual cubic ink can be smaller. The sampled
command grammar uses a one-byte operation followed by signed, absolute
little-endian coordinates in glyph units.

| Operation | Bytes | Geometry |
| --- | ---: | --- |
| 0 | 5 | Move to a new contour start |
| 1 | 5 | Line to one endpoint |
| 2 | 13 | Cubic with two controls and one endpoint, in that order |

Every drawn contour in the three faces reaches its own start again.
The grammar admits multiple contours and disconnected pieces, including
counter shapes and accents. Marin's space has moves with no drawn segments.
Cobb and Dixon have empty command streams for space. Empty glyphs still
have an entry in the nominal advance table.

| Face | Records | Moves | Lines | Cubic commands | Empty streams | Maximum moves in one glyph |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Cobb | 224 | 386 | 1,886 | 2,877 | 13 | 7 |
| Dixon | 224 | 397 | 1,912 | 1,436 | 4 | 7 |
| Marin | 224 | 391 | 2,168 | 2,329 | 12 | 7 |

All 645 present auxiliary sections have word 2 followed by two counts.
Each count accounts for six bytes per row. The remaining 27 records have
zero auxiliary bytes. Several rows correspond to paired X or Y edges of
simple capitals, suggesting a role in grid fitting. The renderer retains
the bytes and leaves their behavior open. The independent renderer uses
nonzero winding per glyph, with adjacent glyphs painted independently.

Use `PYTHONPATH=src` and
[draw_ff1_outline_inventory.py](../../tools/experimental/draw_ff1_outline_inventory.py)
with the three pinned local resources to reproduce the counts. The tool
emits aggregate facts and hashes. The parser reports unknown operations with
character code and glyph-relative byte offset. Synthetic portable tests
exercise signed coordinates, line and cubic operations, malformed streams,
and a filled glyph with a counter.

## Initial shared rendering

`python -m deskmate_formats.draw INPUT.FIG --svg --ff1 LOCAL.FF1`
projects the supported base face into SVG. Repeat `--ff1` for more local
families. The shared `preview_svg` and `preview_rsx` APIs take the same
loaded face mapping. The serialized descriptor identifies the requested
family, point size, width percentage and candidate origin words at 92–95.
The implementation places paths at that origin using 1,000 world units
per inch, 72 points per inch, the inner em word, and nominal advances.
The raster projects the same cubics at Normal zoom and scan-converts the
flattened contours at pixel centers. SVG retains the original cubics.
Local resolution uses the base resource name and rejects ambiguous names
from different files. Other transforms and styles remain outside this
profile. Both projections retain omission diagnostics.

The frozen Cobb typography crop gains substantial overlap with independent
outlines. Visible scale, advances and edge quantization still differ in
some runs. At the measured Draw settings, changing palette slot 1 from
yellow to magenta changed all 1,477 ink pixels in the native two-face control
and preserved the mask exactly. The SVG and raster now use entry 1 for these
outlines. Changing `Uf` byte 20 alone from 1 to 2 instead changed glyph
geometry while retaining yellow. Earlier code treated this byte as a
color candidate. Its complete mode semantics are still open.

The `TYPE0`–`TYPE2` records name Cobb, Dixon and Marin respectively.
With byte 20 set to 10 all three drawings repainted identically as Cobb.
The `FAM0`–`FAM2` controls change only the byte-20 value to 1 on each
record. That restored each distinct resource, even with the deliberately
oversized cached rectangle retained. The 20-label grids use 48 pt at 100%
width for the single-character and pair trials, plus two additional
point-size and width combinations. Pure nominal advances and unhinted
outline filling give foreground overlap of 80.2% for Cobb, 87.9% for Dixon,
and 83.6% for Marin on these complete private grids.

At 48 pt and 100% width, the Marin `AV` and `VA` rightmost ink is within
one pixel of the nominal-advance model. Applying the table words directly
as em units would shift the second character by roughly 13 and 12 pixels.
Replacing only the Marin `AV` word from −244 to 0 on the disposable disk
also left every visible pixel of `FAM2` unchanged. This experiment rules
out that stored word producing a visible `AV` displacement in this
profile. Pair adjustment activation in other paths and finer rounding
remain open. The independent renderer uses nominal advances.

The isolated coordinate trial changed one Dixon `I` line endpoint X
from 186 to 140, with directory, other path coordinates and auxiliary
bytes preserved. The changed resource produced 127 pixel differences
in the Dixon grid, including the isolated `I`. The mutation and pair
control offsets are 9,006 and 55,224 relative to their respective FF1
files. Read-back hashes for both mutated resources match the planned
copies in the private `mutations.json` receipt.

## Oblique lines and slanted brushes

The isolated line grids cross four weights and eight styles with
horizontal, vertical, shallow/steep positive and negative slopes,
45-degree stepping, endpoint reversals and a fractional-coordinate trial.
Run [draw_raster_controls.py](../../tools/experimental/draw_raster_controls.py)
with the frozen primitive chart as the profile source and a private
destination. The input candidates and stable repaint receipts are under
`draw-ii-20261119/raster`.

At Normal zoom the nine oblique grids contain 288 line trials. The
independent renderer matches the entire 640 × 418 RGB crop on all nine
grids, including the fractional-input and endpoint-reversal cases. The
model computes the nearest minor-axis pixel at each major-axis step. An
exact half-step takes the center nearer the lower major coordinate,
in either traversal direction. The dash index counts inclusive steps
from the stored start. The thickness comes from stamping a square at
each active center.

| Weight | Square offsets per coordinate | Dash source |
| ---: | --- | --- |
| 0 | 0 | Measured 1-pixel pattern |
| 1 | 0 to 1 | Separate center patterns, with the stamp joining adjacent centers |
| 2 | −1 to 2 | Solid across the tested styles |
| 3 | −2 to 3 | Solid across the tested styles |

For example, a 53-center 45-degree line at weight 2 covers 380 pixels.
An initial 4 × 4 stamp adds 16 pixels and each diagonal step adds seven.
The measured style 2 at weight 1 stamps phase 6 of each eight-step period.
This explains a two-column dash without stretching or masking a thicker
solid line. The previously matched 64 axis color masks remain exact.
The new isolated horizontal and vertical grids expose a separate
weight-1/style-3 discrepancy with the existing axis pattern at their
tested lengths. The profile preserves the established axis results.
Dash phase and shape clipping at newly selected zooms remain open.

Brush trials use two-point `UP` records with eight width encodings.
At widths 17, 18 and 19, a horizontal segment sweeps a slanted nib
across four, eight or twelve rows. At width 18 the rows advance one
pixel left for each pixel down, from `(+4,−3)` to `(−3,+4)` in the
forward control. Steep strokes and the reverse controls show extra edge
pixels and a phase shift. The renderer approximates the area swept by
the nib with a scan-converted quadrilateral along each segment. It
preserves closure and the unfilled interior of the earlier default
Filled Brush capture. The 16 encoding behaves differently and remains
open. The archived freehand brush and closed outline improve from
11.16% to 97.77% foreground overlap. The new projection accounts for
4,359 foreground pixels versus 4,440 in the native frame.

The [FF1 milestone](../../examples/draw-comparison/v1/vga-ff1-03/README.md)
and [pen milestone](../../examples/draw-comparison/v1/vga-pen-04/README.md)
each compare 23 fresh native crops with new independent PNGs and SVGs.
The pen recapture used the same starting disk and frozen fixtures with
the original fonts. The second clone ended at 352,476 emulated ms and

## Continuation

Use the first native grids and the disposable coordinate mutation
as the anchor for grid fitting. Trace marker-2 auxiliary rows and the
native interpretation of `Uf` bytes 20 and 21. Compare one row at a
time against `fontchk`, `clr20`, `clr21` and `cgeom` at the same
thresholds before pursuing kerning and cached-width recalculation.
The prior Ghidra workspace and stripped MZ mapping are pinned in the
[recovery handoff](draw-recovery-handoff-20261119.md). Rotated and
outline-only FF1, exact scan conversion and embedded stroke text
placement need controls of their own.

For raster work, use the new line masks as regression anchors and
discriminate axis style 3 at two lengths and framebuffer phases.
Measure brush byte 16, nib end-cap phase, and single strokes at more
angles. Then compare native ellipse edges and reduced-zoom page
boundaries. The browser still needs a separate nearest-neighbor
RSX display mode and fuller native dialogs. New packed-list mutations
should begin with small native acceptance trials for arcs, nested
groups and graphical text changes.
