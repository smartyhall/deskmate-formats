# Research, evidence, and the project

This reference is also a record of an ongoing preservation effort. The research section explains how our claims are obtained and where the remaining questions lie. Readers looking for an introduction to the original software should begin with [Discover DeskMate](../history/introduction.md); readers trying to recover files should begin with [the recovery guide](recovery-overview.md).

## Native experiments

We use original DeskMate applications in controlled emulator environments to create synthetic files, observe their behavior, and compare the resulting bytes. The following reports document particular experiments and should be read in the context of their tested versions.

- [Filer native experiments](../research/filer-native-20261117.md) — controlled records and database structures.
- [Corkboard and Home Organizer storage](../research/deskmate-corkboard-20261123.md) — note-buffer equivalence and comparisons of separate application databases.
- [Text native experiments](../research/text-native-20261117.md) — original text saves and measured controls.
- [Native graphics experiments](../research/graphics-native-20261117.md) — original Draw objects and shared graphics containers.
- [Worksheet native experiments](../research/worksheet-native-20261117.md) — cell values, formulas, and record evidence.
- [Print Companion and native printing](../research/print-companion-20261123.md) — original application documents, captured printer commands, and a reconstructed page.

The [Technical reference](technical-overview.md) brings these findings together with the original Tandy developer material. Other native experiments, including Sound, Music, and Automatic House, can be reached from the appropriate subject overviews.

## Images and verification

Screenshots in the reference are documentary captures, not newly invented illustrations of historic interfaces. Our [first visual-evidence inventory report](../research/visual-evidence-first-pass-20261120.md) explains an early inventory of the private captures and its limitations. The [visual-evidence curation policy](../visual-evidence-curation.md) and [visual asset publication workflow](visual-assets.md) explain how examples are selected, attributed, and prepared for publication without redistributing original software or private evidence.

The source references associated with each report distinguish a historical claim, manufacturer description, native observation, and interpretation. The [TVDog index review](../ecosystem/tvdog-directory-index-review.md) provides a corresponding example for software acquisition and archive provenance.

## How the project is organized

The [preservation ecosystem roadmap](../preservation-roadmap.md) describes the longer-term boundaries between native format research, reference documentation, tools, and archival infrastructure. The [core format and application workplan](format-workplan.md) outlines the technical questions that guide further investigation.

For readers interested in the website itself, the [reference-site planning notes](README.md) explain its source map and publication model, while the [authoring and migration conventions](authoring.md) describe durable identifiers, evidence roles, and editorial requirements. These are project documents, not parts of the original DeskMate manual.

The project is maintained in the [source repository](https://github.com/smartyhall/deskmate-formats). Original commercial software and private archive material are not redistributed through the site.
